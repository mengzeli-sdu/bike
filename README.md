# 基于 STM32 与 ODrive 的室外无人驾驶平衡自行车控制系统


## 项目简介

本仓库用于整理和展示本人在 **2025 年第二十届全国大学生智能汽车竞赛全国总决赛室外无人驾驶自行车挑战赛** 中参与完成的室外无人驾驶平衡自行车控制系统。

项目以真实自行车平台为载体，围绕 **动态平衡控制、视觉循迹、避障状态切换、人行道停车等待、终点停车保持平衡** 等任务展开。系统以 STM32 为主控，通过 IMU 获取车体姿态信息，通过 ODrive 控制飞轮电机与后轮电机，通过摄像头串口信息完成路径识别与任务状态切换，最终实现无人驾驶自行车在室外赛道上的稳定运行。

本项目代码主要位于 `src/` 目录下，整体采用：

> **飞轮平衡控制 + 视觉循迹控制 + 车辆状态机任务调度**

的控制框架。

## 项目背景

室外无人驾驶自行车挑战赛不同于普通四轮智能车项目。普通智能车主要关注路径识别、转向控制和速度控制，而无人驾驶自行车还必须解决 **低速平衡与停车保持姿态** 的问题。

自行车本身具有欠驱动特性，低速和停车时极易失稳。因此，本项目不仅要让车辆能够根据摄像头完成循迹，还要在避障、人行道停车和终点停车等任务中持续保持车体平衡。

本项目需要解决的主要问题包括：

- 自行车低速运行时的动态平衡控制；
- 摄像头识别赛道并通过串口发送偏差信息；
- 根据视觉偏差完成正常循迹；
- 遇到障碍物时进入避障状态，并根据编码器记录行驶距离；
- 遇到人行道信息时停车等待 30 秒，同时保持车体平衡；
- 到达终点后永久停车，但仍然保持平衡；
- 通过状态机协调平衡、循迹、避障、停车等多种任务逻辑。

## 系统总体方案

本项目采用 STM32 作为主控核心，结合 IMU、摄像头、ODrive 电机控制器、飞轮电机、后轮电机和编码器等模块，实现室外无人驾驶自行车控制。

系统整体流程如下：

```text
摄像头识别赛道信息
        ↓
UART7 串口发送偏差与任务标志
        ↓
STM32 主控解析视觉信息
        ↓
车辆状态机判断当前任务
        ↓
正常循迹 / 避障 / 人行道停车 / 终点停车
        ↓
舵机或转向机构执行路径修正
        ↓
ODrive 控制后轮速度与飞轮速度
        ↓
IMU 姿态反馈
        ↓
飞轮平衡控制
```

系统核心思想是：

> **平衡控制始终保持运行，任务状态只改变后轮速度、循迹策略和停车逻辑。**

也就是说，无论车辆处于正常行驶、避障、人行道等待，还是终点停车状态，系统都不会直接关闭平衡控制，否则自行车会失稳倒下。

## 核心控制逻辑

本项目采用分层控制结构：

### 1. 底层平衡控制

通过 IMU 获取车体横滚角和角速度，利用飞轮电机输出反作用力矩，使自行车在行驶和停车时都能够保持姿态稳定。

```text
车体倾角
    ↓
角度环 PID
    ↓
目标角速度
    ↓
角速度环 PID
    ↓
飞轮速度指令
    ↓
飞轮产生反作用力矩
    ↓
车体恢复平衡
```

### 2. 中层运动控制

通过 ODrive 控制后轮电机速度，实现车辆前进、停车、低速保持和任务切换。

### 3. 上层任务状态机

根据摄像头发来的任务信息，在正常循迹、避障、人行道等待和终点停车之间切换。

```text
摄像头任务标志
    ↓
车辆状态机
    ↓
正常循迹 / 避障 / 人行道停车 / 终点停车
```

## 车辆状态机设计

为了让车辆能够稳定完成比赛任务，本项目设计了四种主要状态：

```c
typedef enum
{
    CAR_NORMAL = 0,       // 正常循迹 + 平衡
    CAR_AVOID,            // 避障状态：循迹 + 编码器计距
    CAR_CROSSWALK,        // 人行道状态：停车 30s + 原地平衡
    CAR_FINISH            // 终点状态：永久停车 + 保持平衡
} CarState;
```

### 1. 正常循迹状态

正常情况下，摄像头持续通过串口发送赛道偏差信息。主控根据偏差控制转向机构，同时保持后轮以设定速度运行。

```text
摄像头偏差
    ↓
循迹控制
    ↓
转向修正
    ↓
后轮保持基础速度
    ↓
飞轮持续平衡
```

### 2. 避障状态

当摄像头识别到障碍物并发送避障信息时，车辆进入避障状态。

避障状态下，车辆并不是停止循迹，而是：

- 继续根据摄像头偏差进行循迹；
- 同时开启编码器路程记录；
- 当编码器累计值达到设定阈值后，认为避障段已经通过；
- 主控通过串口通知摄像头退出避障状态；
- 编码器计数清零；
- 车辆回到正常循迹状态。

控制流程如下：

```text
摄像头发送避障信息
        ↓
进入 CAR_AVOID 状态
        ↓
继续循迹
        ↓
编码器累计行驶距离
        ↓
距离达到阈值
        ↓
串口通知摄像头退出避障
        ↓
编码器清零
        ↓
回到正常循迹状态
```

### 3. 人行道停车状态

当摄像头识别人行道并发送人行道信息时，车辆进入停车等待状态。

该状态下：

- 后轮速度清零；
- 转向机构回中；
- 飞轮平衡控制继续运行；
- 等待 30 秒；
- 30 秒后恢复正常行驶。

控制流程如下：

```text
摄像头发送人行道信息
        ↓
后轮速度清零
        ↓
车辆原地保持平衡
        ↓
等待 30s
        ↓
恢复正常循迹
```

### 4. 终点停车状态

当摄像头识别到终点并发送终点信息时，车辆进入终点状态。

该状态下：

- 后轮速度永久清零；
- 转向机构回中；
- 不再响应正常循迹、避障、人行道等其他任务；
- 飞轮平衡控制持续运行，使自行车停车后仍能保持姿态。

控制流程如下：

```text
摄像头发送终点信息
        ↓
进入 CAR_FINISH 状态
        ↓
后轮速度永久清零
        ↓
继续保持车体平衡
```

## 串口通信设计

本项目中，摄像头与 STM32 之间通过 UART7 通信。摄像头负责识别赛道与任务标志，STM32 负责解析信息并执行车辆控制。

### 摄像头发送给 STM32

数据帧格式如下：

```text
帧头    命令字    偏差高 8 位    偏差低 8 位    校验
0xA5    CMD       ERR_H          ERR_L          XOR
```

命令字设计如下：

| 命令字 | 含义 |
|---|---|
| `0x01` | 正常循迹数据 |
| `0x02` | 避障信息 |
| `0x03` | 人行道信息 |
| `0x04` | 终点信息 |

### STM32 发送给摄像头

当避障距离达到设定阈值后，STM32 通过串口通知摄像头退出避障状态：

```text
帧头    命令字    校验
0xA5    0x81      XOR
```

其中：

| 命令字 | 含义 |
|---|---|
| `0x81` | 通知摄像头退出避障状态 |

## 关键任务调度

本项目使用 TIM3 作为主控制定时器，周期为 2ms。

TIM3 中断中主要完成：

```text
1. 读取 IMU 姿态数据
2. 执行车辆状态机
3. 根据当前状态更新后轮速度、转向和编码器计数
4. 执行飞轮平衡控制
5. 通过 CAN 向 ODrive 发送飞轮和后轮速度指令
```

伪代码如下：

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if(htim == &htim3)
    {
        imu_get();

        Car_2ms_Task();

        if(param.scope_flag == 1)
        {
            balance();
        }

        odrive_speed_ctrl(0, odrive.set_speed0);   // 飞轮
        odrive_speed_ctrl(1, -odrive.set_speed1);  // 后轮
    }
}
```

## 避障距离记录

避障状态下，系统使用编码器记录车辆通过避障区域的距离。

基本逻辑如下：

```text
进入避障状态
        ↓
编码器清零
        ↓
车辆继续循迹前进
        ↓
周期性读取编码器计数
        ↓
累计距离达到阈值
        ↓
通知摄像头退出避障
        ↓
编码器再次清零
```

伪代码如下：

```c
if(car_state == CAR_AVOID)
{
    Line_Track_Control(camera_error);
    Encoder_UpdateAvoidDistance();

    if(avoid_encoder_count >= AVOID_EXIT_COUNT)
    {
        Camera_SendCmd(MCU_CMD_AVOID_EXIT);
        Encoder_Reset();
        car_state = CAR_NORMAL;
    }
}
```

## 技术要点

### 1. 平衡控制与任务控制解耦

项目中平衡控制是底层稳定性保障，任务状态机是上层行为逻辑。两者解耦后，即使车辆进入人行道或终点停车状态，也不会关闭平衡控制。

### 2. 状态机管理复杂任务

通过 `CAR_NORMAL`、`CAR_AVOID`、`CAR_CROSSWALK`、`CAR_FINISH` 四种状态，将复杂比赛任务拆分为清晰的控制逻辑，降低程序耦合度。

### 3. 避障过程保留循迹能力

避障状态下车辆并非盲目直行，而是继续接收摄像头偏差信息进行循迹，同时利用编码器判断避障距离。

### 4. 停车状态保持平衡

人行道和终点状态下，系统只清零后轮速度，不关闭飞轮平衡控制，使自行车能够在低速或静止状态下维持姿态稳定。

### 5. 多外设协同控制

项目同时涉及 UART、CAN、TIM、PWM、I2C 等外设，要求各模块之间具有较好的实时性和协调性。

## 调试经验

在实车调试中，需要重点关注以下问题：

- 平衡零点是否准确；
- IMU 安装方向是否与程序坐标定义一致；
- 飞轮转向是否与控制输出方向匹配；
- 后轮速度过低时是否会导致车辆失稳；
- 人行道停车时是否仍然保持平衡控制；
- 避障距离阈值是否与实际赛道长度匹配；
- 摄像头识别信息是否存在误触发；
- 串口通信是否存在丢帧或解析错误；
- ODrive CAN 通信是否稳定；
- 电池电压下降后控制参数是否仍然适用。
